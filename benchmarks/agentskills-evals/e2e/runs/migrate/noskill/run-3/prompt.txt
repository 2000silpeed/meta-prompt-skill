레거시 Express API 서버(JavaScript)를 TypeScript로 점진적으로 옮기는 작업을 맡기려고 해.
한 번에 다 바꾸는 게 목표가 아니야. JS와 TS가 함께 돌아가는 상태를 만들고, 그 상태에서 파일을 하나씩 안전하게 옮겨 가는 게 목표야.

## 지켜야 할 원칙
1. **동작은 바꾸지 않는다.** 이번 작업은 타입을 붙이는 리팩터링이야. API 응답, 상태 코드, 에러 메시지, 미들웨어 순서가 바뀌면 안 돼. 변환 중에 버그를 발견해도 직접 고치지 말고 목록에만 남겨 줘.
2. **매 단계가 끝날 때마다 초록불이어야 한다.** 단계가 끝나면 `tsc --noEmit`, jest 전체, lint를 모두 통과해야 해. 하나라도 깨진 상태로 다음 단계에 들어가지 마.
3. **테스트를 맞추려고 테스트를 고치지 않는다.** 기존 테스트의 assertion은 바꾸지 마. 테스트 파일을 TS로 바꾸는 건 별도 단계에서 하고, 그때도 검증하는 내용은 그대로 유지해.
4. **`any`로 덮지 않는다.** 정말 어쩔 수 없을 때만 `unknown`과 타입 가드를 쓰고, 그래도 안 되면 `// TODO(ts-migration): 이유`를 붙인 `any`를 허용해. 이런 곳은 전부 목록으로 보고해 줘. `@ts-ignore`는 쓰지 말고, 꼭 필요하면 이유를 적은 `@ts-expect-error`를 써.
5. **모듈 방식(CJS/ESM)은 이번에 바꾸지 않는다.** 지금 쓰는 방식을 그대로 유지해.

## 진행 순서
### 0단계: 조사 (코드를 수정하기 전에)
- 디렉터리 구조, 진입점, 파일 사이의 의존 관계를 파악해. 어떤 파일이 아무것도 import하지 않는 말단(leaf)인지 확인하는 게 핵심이야.
- `package.json` 스크립트, jest 설정, CI 워크플로, 배포 시작 명령을 확인해.
- 동적 `require`, `module.exports` 재할당, `req`/`res`에 붙이는 커스텀 속성(예: `req.user`)처럼 변환을 어렵게 만드는 패턴을 찾아 둬.
- 조사한 내용으로 변환 순서(말단 → services → middleware → routes → 진입점)를 정하고 `MIGRATION.md`에 적어 줘.

### 1단계: 기반 설정
- `typescript`와 `@types/node`, `@types/express`, `@types/jest`, 그 밖에 필요한 `@types/*`를 설치해.
- `tsconfig.json`을 만들고 `allowJs: true`, `checkJs: false`, `strict: true`로 설정해. 레거시 JS 파일은 타입 검사에서 빠지고, 새 TS 파일만 strict로 검사되게 하려는 거야. `outDir`도 지정해.
- jest가 `.ts`를 실행할 수 있게 설정해. ts-jest와 @swc/jest 중 무엇을 고를지는 이 저장소에 맞게 판단하고, 고른 이유를 적어 줘.
- `typecheck` 스크립트(`tsc --noEmit`)를 추가하고 CI 워크플로에 같은 단계를 넣어.
- `req`/`res` 커스텀 속성은 `src/types/express.d.ts`에서 declaration merging으로 정의해.
- 이 단계에서는 JS 파일을 하나도 변환하지 않아. 기존 테스트가 모두 그대로 통과하는지만 확인해.

### 2단계 이후: 파일 변환
- `MIGRATION.md`에 적은 순서대로, 작은 묶음(대략 3~8개 파일)씩 `.js`를 `.ts`로 바꿔.
- 확장자 변경과 내용 수정은 커밋을 나눠 줘. `git mv`로 이름만 바꾸는 커밋을 먼저 하고, 타입을 추가하는 커밋을 그다음에 해. 그래야 diff를 리뷰하기 쉬워.
- 요청 body, params, query는 [zod 등 기존에 쓰는 검증 라이브러리가 있으면 그걸로 / 없으면 인터페이스로] 타입을 정의해. 라우트 핸들러는 `Request<Params, ResBody, ReqBody, Query>` 제네릭을 써서 타입을 붙여.
- 묶음 하나가 끝날 때마다 typecheck, jest, lint를 실행하고 커밋해. 커밋 메시지 형식은 `refactor(ts): convert src/utils/* to TypeScript`처럼 맞춰 줘.

## 빌드와 배포 (주의할 부분)
- 실행 방식을 바꾸는 작업(`tsc` 빌드 후 `node dist/...`로 실행, Dockerfile이나 start 스크립트 수정 등)은 운영에 직접 영향을 줘. 그래서 **이번 범위에서는 계획만 세워서 `MIGRATION.md`에 적고, 실제 변경은 하지 마.** 진입점까지 변환이 끝난 다음에 별도로 진행할 거야.
- 진입점을 변환하기 전까지는 기존 시작 명령이 그대로 동작해야 해.

## 멈추고 보고해야 하는 경우
아래 상황이 생기면 추측해서 진행하지 말고, 그때까지 한 작업을 커밋한 다음 질문을 정리해서 멈춰 줘.
- 타입을 붙이려면 런타임 동작을 바꿔야 하는 경우
- 이미 실패하는 테스트가 있거나, 실행할 때마다 결과가 달라지는 flaky 테스트를 발견한 경우 (작업 전 기준 결과를 먼저 기록해 둬)
- 의존성 메이저 버전을 올리지 않으면 진행할 수 없는 경우
- CI 시크릿, 배포 설정, 환경 변수를 건드려야 하는 경우
