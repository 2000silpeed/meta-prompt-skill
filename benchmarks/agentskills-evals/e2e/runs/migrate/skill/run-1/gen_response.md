레거시 Express(JavaScript) API 서버를 TypeScript로 점진 마이그레이션해 줘. 운영 중인 서버이므로 각 단계가 끝날 때마다 서버가 그대로 빌드·실행되고 기존 jest 테스트와 GitHub Actions CI가 통과하는 상태여야 해. 한 번에 전부 바꾸지 말고 JS와 TS가 같이 돌아가는 상태를 유지하면서 파일 단위로 옮겨.

## 목표와 이번 작업 범위
- 최종 목표: 모든 서버 코드를 .ts로 옮기고 strict 타입 체크를 통과시키는 것.
- 이번 실행 범위: {예: "1단계 인프라 + 의존성 없는 말단 모듈(utils, 상수, 순수 함수)까지" — 비워 두면 1~3단계까지만 하고 멈춰}
- 바깥에서 보이는 동작은 바꾸지 마. 라우트 경로, 응답 JSON 구조, 상태 코드, 헤더, 에러 메시지가 그대로여야 해. 클라이언트가 이 API에 의존하고 있어서 타입을 정리하다가 생긴 동작 변화도 장애가 돼.

## 진행 순서
1. **사전 조사 (코드는 바꾸지 마)**
   - Node 버전, 모듈 시스템(CommonJS/ESM), 패키지 매니저, 엔트리포인트, start/build/test 스크립트, jest 설정, `.github/workflows/` 아래 워크플로를 확인해.
   - 지금 상태에서 테스트를 돌려서 기준선(통과/실패/스킵 수)을 기록해. 이미 실패하는 테스트가 있으면 고치지 말고 목록만 남겨.
   - 모듈 의존 그래프를 대략 그려서 변환 순서(말단 → 상위, 라우터·app 조립은 마지막)를 정해.
   - 동적 require(`require(path.join(...))`, 디렉터리를 돌며 라우트를 자동 등록하는 코드), `__dirname` 기반 경로, JSON·템플릿 같은 비코드 파일 로딩, monkey-patching, `req`에 붙이는 커스텀 속성(`req.user` 등)을 찾아서 목록으로 만들어. 컴파일 결과물 위치가 바뀌면 여기서 문제가 생겨.

2. **인프라 도입 (동작 변화 없이)**
   - typescript와 @types/node, @types/express, @types/jest 등을 devDependencies에 추가해. 기존 런타임 의존성 버전은 올리지 마.
   - tsconfig는 `allowJs: true`, `checkJs: false`로 시작하고 기존 모듈 시스템에 맞춰. 처음부터 `strict: true`로 두되 변환한 파일에만 적용되게 해. JS 파일까지 strict를 강제하면 첫 단계부터 에러가 수천 개 나와.
   - 빌드 방식(tsc → dist, 또는 tsx/ts-node 실행)을 고르고 이유를 보고서에 적어. dist로 빌드한다면 비코드 파일 복사와 `__dirname` 경로가 깨지지 않는지 확인해.
   - jest는 ts-jest나 babel 중 기존 설정에 맞는 쪽으로 .ts를 처리하게 해. babel을 쓰면 타입 체크를 하지 않으니 별도 `typecheck` 스크립트(`tsc --noEmit`)를 반드시 추가해.
   - CI 워크플로에 typecheck 단계를 추가해. 기존 단계는 지우거나 순서를 바꾸지 마.

3. **파일 단위 변환 (반복)**
   - 한 번에 한 모듈 또는 밀접한 소수 파일만 .js → .ts로 바꾸고, 바꿀 때마다 typecheck와 jest를 돌려.
   - `module.exports` → `export`로 바꿀 때 아직 JS인 호출부에서 `require()`가 `.default`를 받게 되는 interop 문제를 확인해. 호출부가 남아 있으면 export 형태를 호환되게 유지해.
   - `any`는 경계(외부 입력, 타입 없는 라이브러리)에서만 쓰고, 쓸 때마다 `// TODO(ts):` 주석으로 이유를 남겨. `req.body`, `req.query`처럼 외부에서 들어오는 값은 타입 단언으로 덮지 말고 `unknown` 또는 검증 지점을 명시한 타입으로 받아.
   - Express 에러 미들웨어는 인자 4개 시그니처가 유지돼야 등록되니 인자를 줄이지 마. `req`의 커스텀 속성은 declaration merging(`declare global { namespace Express { ... } }`)으로 선언해.
   - 타입 에러를 피하려고 로직을 바꾸지 마. 타입을 붙이다가 실제 버그(undefined 접근, 잘못된 비교 등)를 발견하면 고치지 말고 보고서에 위치와 내용을 적어.

## 하지 말고 보고할 것
- 기존 테스트의 기대값 수정, 테스트 삭제·skip. 테스트 파일을 .ts로 옮기는 것은 괜찮지만 단언 내용은 그대로 둬.
- DB 스키마, 마이그레이션 파일, 환경변수 이름, 외부 API 연동 방식 변경.
- 런타임 의존성 추가·메이저 업그레이드, Node 버전 변경.
- git push, PR 생성, main 브랜치 직접 커밋. 작업 브랜치에서 의미 단위로 로컬 커밋만 해.
- 실제 DB, 외부 결제·메일 등 부작용이 있는 서비스 호출과 운영 데이터·시크릿 접근. 테스트에 필요하면 기존 mock·테스트 설정만 써.

## 완료 조건
- `tsc --noEmit`, jest 전체, 그리고 가능한 범위에서 CI와 같은 명령이 로컬에서 통과하고, 테스트 결과가 1단계 기준선보다 나빠지지 않을 것.

- 위 명령들을 실제로 실행해서 확인했을 때만 완료로 보고해. 실행하지 못한 검증은 "미검증"으로 따로 적어.
