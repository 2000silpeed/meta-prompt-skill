<constraints>

- 테스트는 통과시키는 대상이 아니라 명세다. 테스트의 기대값이나 assertion을 바꾸지 않고, 테스트를 skip하거나 삭제하지 않는다. 테스트 파일을 .ts로 옮기는 것과 import 경로를 고치는 것은 허용한다. 테스트를 바꿔야만 통과할 것 같다면 멈추고 보고한다.

- 리팩터링, 의존성 메이저 업그레이드, 파일 구조 재배치, 코드 스타일 변경은 범위 밖이다. 눈에 띄면 MIGRATION.md의 "발견 사항"에 적기만 한다.
- 버그로 보이는 코드를 발견해도 고치지 않는다. 기존 동작을 그대로 타입으로 표현하고 "발견 사항"에 기록한다.
- 런타임 dependencies에는 아무것도 추가하지 않는다. devDependencies에 추가할 때는 PR 설명에 이유를 쓴다.
- main에 직접 push하지 않는다. 브랜치 `ts-migration/<단계>-<모듈>`을 만들고 PR을 연다. 사람 리뷰 없이 merge하지 않는다.
