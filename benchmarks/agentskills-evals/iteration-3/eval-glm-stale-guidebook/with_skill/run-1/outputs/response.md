# 조사 지침
"가끔" 틀린다는 것은 특정 값에서만 틀린다는 뜻일 가능성이 높다. 다음을 우선 의심하고, 각 항목을 코드에서 확인했는지 여부를 기록하라.
1. 부동소수(float/double/JS number)로 금액을 계산하거나 저장함. 예: 1.005*100 = 100.49999…
2. float을 Decimal/BigDecimal로 바꿀 때 정밀도가 깨짐. Decimal(1.005)는 1.00499999…가 된다. 문자열이나 정수 최소단위에서 생성해야 한다.
3. 반올림 모드 불일치. Python round()와 Java의 기본값은 HALF_EVEN(은행가 반올림)이고, JS toFixed는 이진 표현 때문에 결과가 틀릴 수 있다. 경로마다 서로 다른 함수를 쓰는지 확인하라.
4. 반올림 시점 불일치. 품목별로 반올림한 뒤 합산한 값과 합산한 뒤 반올림한 값이 다르다. 세금·할인·수수료·분할결제·환불 경로를 비교하라.
5. 통화별 소수 자릿수를 하드코딩함. KRW·JPY는 0자리, USD는 2자리, KWD·BHD는 3자리다.
6. 음수 금액(환불·취소)의 반올림 방향.
7. DB 컬럼이 FLOAT/DOUBLE이거나 직렬화(JSON)할 때 숫자로 변환하는 부분.
