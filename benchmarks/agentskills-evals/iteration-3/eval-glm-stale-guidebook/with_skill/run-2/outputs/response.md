# 흔한 원인 (해당 여부를 하나씩 확인)
- 금액을 부동소수(float/double, JS number)로 계산하거나 저장한다. 0.1 + 0.2, 1.005 × 100 같은 값에서 깨진다.
- float를 decimal로 변환할 때 이미 정밀도가 손실된다. 예: Python `Decimal(1.005)`는 1.00499999…가 된다. 반드시 문자열이나 정수 최소단위에서 생성해야 한다.
- 반올림 모드가 섞여 있다. Python `round()`는 은행가 반올림(half-even)이고, JS `Math.round`는 음수에서 동작이 다르고, `toFixed`는 이진 표현 그대로 반올림한다.
- 반올림 시점이 다르다. 항목별 반올림 후 합산과 합산 후 반올림은 결과가 다르다. 계산 중간에 반올림하는 곳도 확인한다.
- 분할 결제·할부·부분 환불에서 나눈 금액의 합이 원금과 맞지 않는다(나머지 처리 누락).
- 통화별 소수 자릿수를 하드코딩했다. KRW·JPY는 0자리, USD는 2자리, KWD·BHD는 3자리다.
- DB 컬럼 타입(FLOAT/REAL)이나 JSON 직렬화 과정에서 정밀도가 손실된다.
