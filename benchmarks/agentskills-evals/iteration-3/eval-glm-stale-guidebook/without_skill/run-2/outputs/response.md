# 작업: 결제 모듈의 금액 반올림 오류 수정

## 배경
결제 모듈에서 가끔 금액의 소수점 반올림 결과가 틀린다. 항상 틀리는 게 아니라 특정 금액에서만 1원(또는 최소 화폐 단위 1) 정도 어긋나는 것으로 보인다.
- 관련 위치(아는 경우): [예: src/payment/, PriceCalculator 등]
- 실제로 본 사례(있는 경우): [예: 입력 1,234.565 → 기대 1,234.57, 실제 1,234.56]
- 비즈니스 규칙(아는 경우): [예: 사사오입(HALF_UP), 부가세는 원 단위 절사 등]

## 진행 순서
단계를 건너뛰지 말고, 각 단계에서 알아낸 것을 짧게 적으면서 진행해라.

### 1. 조사 (코드 수정 금지)
결제 금액이 계산·변환·저장·표시되는 경로를 모두 찾아라. 특히 아래를 확인해라.
- 금액에 float/double(JS의 number 포함)을 쓰는 곳. 0.1+0.2, 1.005*100 같은 이진 부동소수점 오차가 의심된다.
- 반올림 함수와 반올림 모드: Math.round, round(), toFixed, BigDecimal.setScale, Decimal.quantize, ROUND_HALF_EVEN과 HALF_UP 혼용 여부. Python의 round()는 은행가 반올림이다.
- 반올림 시점: 중간 계산마다 반올림하는지, 마지막에 한 번만 하는지. 항목별로 반올림한 뒤 합산한 값과 합산한 뒤 반올림한 값이 다른 경우가 있는지.
- 할인·쿠폰·부가세·수수료·분할결제·환불처럼 금액을 나누는 계산. 나눈 금액을 다시 더했을 때 원금과 맞는지.
- 통화별 소수 자릿수(KRW/JPY 0자리, USD 2자리 등)를 하드코딩했는지.
- 문자열·숫자 변환(파싱, 직렬화, DB 컬럼 타입, 외부 PG API로 보내는 값).

### 2. 재현
위에서 찾은 의심 지점마다, 현재 코드에서 실패하는 테스트를 먼저 작성해라. 다음 경계값을 반드시 포함해라.
- x.xx5 형태(예: 1.005, 2.675, 1234.565)
- 0, 음수(환불), 아주 큰 금액
- 3으로 나누기 같은 분할 케이스(10000원을 3명이 나눠 내는 경우 등)
- 통화별 자릿수
테스트를 실행해서 실제로 실패하는지 확인하고, 실패 출력을 기록해라.
재현되지 않으면 추측으로 고치지 말고 6번 보고로 넘어가라.

### 3. 원인 확정
각 실패의 근본 원인을 한두 문장으로 써라. 증상만 가리는 수정(예: +0.0000001 보정, 결과 값 땜질)은 금지한다.

### 4. 수정 원칙
- 금액은 정수 최소 단위(원, 센트) 또는 언어의 십진 타입(BigDecimal, decimal.Decimal, decimal.js 등)으로 다뤄라. float로 계산한 뒤 반올림하는 방식은 쓰지 마라.
- 반올림 모드와 시점은 한 곳(유틸 함수나 상수)에서 정해 공통으로 쓰게 해라.
- 반올림 규칙이 코드·문서·테스트에서 확인되지 않으면 기존에 가장 많이 쓰인 동작을 유지하고, 그 사실을 보고에 적어라. 규칙을 임의로 바꾸지 마라.
- 분할 금액은 나눈 값의 합이 원금과 정확히 같아야 한다. 나머지를 어떻게 배분하는지 명시해라.
- 범위: 반올림 버그와 직접 관련된 코드만 고쳐라. 관련 없는 리팩터링, 포맷 변경, 의존성 추가는 하지 마라. 꼭 필요한 의존성이 있다면 이유를 적어라.
- DB 스키마, 외부 PG 연동 포맷, 공개 API 응답 형식은 바꾸지 마라. 바꿔야만 고칠 수 있다면 수정하지 말고 보고에 적어라.

### 5. 검증
- 2단계에서 만든 테스트가 모두 통과하는지 확인해라.
- 기존 전체 테스트 스위트를 실행해서 깨진 테스트가 없는지 확인해라. 기존 테스트의 기대값이 틀린 값을 전제하고 있었다면, 고치기 전에 근거를 보고에 남겨라.
- 린트와 타입체크가 있다면 통과시켜라.

### 6. 최종 보고 (이 형식으로)
1. 근본 원인: 파일:라인과 설명
2. 수정 내용: 변경 파일 목록과 각 변경의 이유
3. 추가한 테스트와 결과: 수정 전 실패, 수정 후 통과
4. 전체 테스트 결과: 통과/실패 개수
5. 동작이 바뀌는 지점: 기존 결제·정산 데이터와 1원 차이가 날 수 있는 케이스
6. 확인이 필요한 사항: 반올림 규칙이 불명확한 곳, 고치지 않고 남겨둔 의심 지점
