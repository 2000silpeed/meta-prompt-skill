# 모델별 일반 지시 vs 메타 프롬프트 A/B

## 질문

같은 모델, 같은 코드와 상세 요구사항, 같은 추론 설정에서 메타 프롬프트의 추가 적용이
정확성·소요 시간에 어떤 차이를 만드는가? 팀 구성은 모든 조건에서 단독이다.

사용자가 지정한 모델: gpt-6-astra, gpt-5.6-sol, gpt-5.6-luna.
네이티브 에이전트의 model 파라미터로 지정하고 reasoning_effort는 모두 medium으로 고정한다.
각 모델 × raw/meta × 2회 = 총 12회. 매번 이전 대화가 없는 새 에이전트와 같은 시작 코드의
별도 복사본을 사용한다. 모델 간 절대 순위보다 모델 내 raw/meta 차이를 먼저 해석한다.

## 두 조건

- raw: “이 작업 폴더의 shop 코드를 CONTRACT.md 요구사항에 맞게 고쳐줘. 테스트로 확인하고 변경 사항과 테스트 결과를 알려줘.”
- meta: 위 요청을 기존 meta-prompt 카드로 재구성한 목표·맥락·제약·완료 기준·결과 형식.

공통 실험 환경, 작업 범위, 도구 권한, 출력 파일·스키마, 같은 상세 CONTRACT.md와 공개 테스트는
두 조건에서 동일하다. raw를 일부러 불완전하게 만들지 않는다. 메타 조건에만 버그 위치나
추가 도메인 정보·정답 힌트를 제공하지 않는다. 메타 프롬프트는 실행 전에 컴파일했으며,
참여 에이전트는 두 조건 모두 스킬 파일을 추가 로딩하거나 재변환하지 않는다.

원래 과제의 Goal/Done when 형태의 실행 지시는 공통 계약에서 제거하고 도메인 요구사항은 유지했다.
하지만 이 계약 자체가 상세하고 구조화되어 있으므로, 이번 실험은 모호한 한 줄 요청을
보완하는 전체 효과가 아니라 **상세 명세가 이미 있는 상황의 추가 프롬프트 효과**를 측정한다.

## 가이드북 적용

- Astra: openai-codex + _generic. 전용 Astra 가이드는 없고 범용 카드는 knowledge-based다.
- Sol: openai-codex + openai-gpt-5의 공통 카드 및 gpt-5.6-sol 카드.
- Luna: openai-codex + openai-gpt-5 공통 카드. Luna 전용 카드는 없다.

모델별 문법 지침의 검증 수준이 같지 않으므로 결과를 모두 완전한 전용 최적화의 효과라고
부르지 않는다. 목표·제약·완료 조건, 코드 검증·형식 규칙만 적용하고 과거 모델 가용성·가격
문구는 사용하지 않았다. 지시 전문은 각 run/prompt.txt에 고정되어 있다.

## 평가와 순서

기존 회귀 평가 40개와 앞 실험에서 발견한 큰 정수 경계값 1개, 총 41개를 첫 실행 전에
동결했다. 이 확장 사례는 앞 실험에서는 사후 탐색이었지만 이번 A/B에서는 양쪽 조건에
같이 적용하는 사전 고정 평가다. 참가자에게 해당 사례의 힌트는 주지 않는다.
초기 코드 20/41, 교정용 수정 코드 41/41을 확인했다.

고정 순서:
1. Astra raw → meta, Sol meta → raw, Luna raw → meta.
2. Luna meta → raw, Sol raw → meta, Astra meta → raw.

이는 실행 전에 정한 순서이며 무작위화 실험은 아니다. 실행끼리 겹치지 않는다.
토큰 상한은 통제하지 않았고 정확한 실제 금액·토큰 수는 계측하지 않는다. 도구 사용과
자체 테스트는 양쪽 모두 가능하며 평가 피드백·부모의 코드 수정은 제공하지 않는다.

측정: 41개 테스트 통과 수, 공개·자체 테스트 결과, 시작 마커부터 completion.json까지의
시간, 실제 요청한 모델·추론 설정, 코드 해시. 시간 기록은 저장하여 checkout의 mtime 변화와
구분한다. 프롬프트 컴파일·평가·보고서 작성 시간은 조건별 수행 시간에 포함하지 않는다.

## 한계와 재현

한 합성 과제, 각 조건 2회다. 통계적 유의성, 전체 서비스의 품질 순위, 비용 효율을 주장하지 않는다.
격리는 지시와 디렉터리 구분에 기반하며 파일시스템 보안 샌드박스가 아니다. 모델 내부의
학습된 프롬프트 이해 능력이나 상위 시스템 지시는 raw에서도 유지된다.

```bash
python3 benchmarks/meta-prompt-ab/grade.py --candidate benchmarks/meta-prompt-ab/runs/r1-astra-raw/work
python3 benchmarks/meta-prompt-ab/report.py
```

이는 재채점이며 새 모델 호출을 하지 않는다. 재실행 시 새 run 디렉터리에 동일 입력을 복사하고
manifest.json의 모델·effort·순서로 실제 네이티브 에이전트를 호출해야 한다.
