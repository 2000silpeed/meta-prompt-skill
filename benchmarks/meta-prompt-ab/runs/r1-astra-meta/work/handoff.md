# 구현 및 검증 기록

기존 public API와 모듈 경계를 유지하면서 CONTRACT.md 요구사항과 구현을 대조했다.

## 변경 사항
- clock: 명시적 시간대가 없는 입력을 거부하고 실제 instant를 UTC로 변환한다.
- money: bool 수치를 거부한다. 할인은 정수 나눗셈과 나머지로 정확하게 배분하며 동률은 SKU 오름차순으로 처리한다. 누적 취소 구간의 floor 차이로 환불을 계산한다.
- inventory: 재고와 요청 전체를 먼저 검증하고, reserve의 모든 수량이 충분한지 확인한 뒤 수정해 실패 원자성을 보장한다.
- engine: 초기 재고와 snapshot의 alias를 제거했다. UTC 정규화와 재귀 키 정렬로 전체 payload fingerprint를 만들고 중복 검사를 시간 검사보다 먼저 수행한다. 이벤트는 내부 상태 복사본에 실행하며 성공 후에만 교체하여 만료·as_of·중복 기록도 함께 롤백된다.
- reserved 주문만 expires_at <= at에 만료하며 confirmed 주문은 TTL로 만료되지 않는다. 예약 부분 취소를 거부하고 기존 취소·환불 상태 전이를 유지했다.
- replay: UTC datetime 기준으로 안정 정렬하며 호출자 입력을 변경하지 않는다.
- tests/test_contract.py에 13개 자체 테스트를 추가했다. 계약과 기존 공개 테스트는 수정하지 않았다.

## 실제 검증
`python3 -m unittest discover -s tests -v`를 실행했다. 최초 수정 후 공개 테스트 6/6 통과, 자체 테스트 추가 후 전체 19/19 통과했다.

자체 검증은 bool·잘못된 입력, 400자리 금액 계산, SKU 동률 및 순서, 여러 수량의 환불 보존, 재고 원자성, 입력 및 snapshot 분리, UTC 중복 재전송, 미지 키 및 lines 순서 fingerprint, TTL 경계 실패 롤백 및 같은 id 재시도, confirmed TTL 제외, 전체·부분 취소, 주문 ID 재사용 거부, UTC replay 안정 정렬과 입력 불변성을 포함한다.

## 한계
관측된 테스트 실패는 없다. 비공개 평가 테스트 결과는 제공되지 않아 확인하지 않았다. 이벤트마다 전체 상태를 복사하므로 처리 비용은 누적 주문 및 중복 기록 크기에 비례한다. 계약상 범위 밖인 다중 스레드·DB·네트워크는 구현하지 않았다.
