# 변경 사항

- public API와 모듈 경계를 유지했다. 원본 CONTRACT.md와 tests/test_public.py는 변경하지 않았다.
- 시간 파싱은 명시적 시간대를 요구하고 실제 instant를 UTC로 변환한다. replay는 UTC datetime으로 안정 정렬한다.
- 할인 배분은 정수 나눗셈과 나머지만 사용하며, 같은 나머지는 SKU 오름차순으로 처리한다. bool 수치를 거부하고 누적 취소 기준의 정확한 환불 차액을 계산한다.
- 재고 요청 전체를 검증하고 충분한 재고를 확인한 뒤 변경하여 실패 시 재고를 보존한다.
- 초기 재고와 snapshot을 깊은 복사한다. apply는 복제한 상태에 만료와 이벤트를 적용하고 성공할 때만 상태 및 중복 기록을 교체한다.
- fingerprint는 전체 payload의 dict 키 순서를 정규화하고 at 및 reserve.expires_at을 UTC ISO로 변환한다. 중복 검사를 시간 역행·만료보다 먼저 수행하며, lines 순서와 미지 키를 보존한다.
- reserved 주문만 expires_at <= at에 만료된다. confirmed 주문은 TTL로 만료되지 않는다. 예약의 부분 취소를 거부하고 확정 후 취소는 최초 금액과 누적 수량에 따라 환불한다.

# 실제 검증

1. `python -m unittest discover -s tests -v`: 초기 수정 후 공개 테스트 6개 통과.
2. 같은 명령을 자체 테스트 추가 후 실행: 공개 6개와 자체 10개, 총 16개 통과 (실패 0).

자체 테스트는 시간대·잘못된 시각, bool·잘못된 금액, 100자리 정수 배분, SKU 동률 규칙, 환불 수식의 작은 정수 범위 전수 대조, 재고 원자성, 입력·snapshot alias 차단, 정규화 중복·충돌·시간 역행, TTL 경계 실패 rollback 및 실패 id 재사용, 만료 order_id 재사용 금지, 부분 취소·누적 환불, 거부된 이벤트 상태 보존, replay UTC 정렬·동시각 순서·입력 불변성을 검증한다.

CONTRACT.md의 수치, 시간·재고, 상태 전이, 중복·원자성, 복사, replay 요구사항을 최종 구현과 대조했다.

# 한계

- 평가용 비공개 테스트는 제공되지 않았으며 실행하지 않았다.
- 원자성은 이벤트마다 전체 내부 상태를 깊은 복사하는 방식이다. 큰 주문 이력에서 시간·메모리 비용이 증가하며 성능 부하 검증은 수행하지 않았다.
- 다중 스레드, DB, 네트워크는 계약에 따라 범위 밖이다.
