# 고난도 프롬프트 제어 비교

2026-10-28. 앞선 작은 과제의 점수 포화를 확인하기 위한 제한된 후속 실험이다.
모든 입력·정답·실행 순서·후보 지시·채택 조건을 첫 실행 전에 해시로 고정한다.

- 기준본은 현재 GPT 카드의 결과 중심 명세를 고정 템플릿으로 수작업 컴파일한다.
  스킬 전체의 자동 호출이나 모델 제공자 벤치마크가 아니다.
- 후보는 같은 자료·목표·출력 계약에 한 가지 검증 묶음만 추가한다.
  정답·구체적 오류 위치·새 도메인 사실을 추가하지 않는다. 개별 팁의 효과로 분해하지 않는다.
- 진단 3과제: 중첩 분류 우선순위, 긴 문서의 유효 개정·원장, 배포 완료 판정.
  확인 3과제: 다른 도메인의 우선순위, 재고 원장, 정확한 문자열·참조 보존.
  확인 과제도 실행 전에 고정하며 진단 결과를 보고 후보를 수정하지 않는다.
- 요청 모델은 gpt-6-luna와 gpt-6.1-terra, effort=low. 각 모델의 기준본/후보를
  2회 반복한다. 비교는 모델 안에서만 한다. 실제 backend/effort는 관측되지 않으면 unknown.
- 3과제를 한 묶음으로 실행한다. 총 16개의 새 native 에이전트, 48개의 과제 결과다.
  독립 단위는 에이전트 묶음이며 같은 묶음 안 과제를 독립 표본으로 간주하지 않는다.
  최대 동시 작업자 3명, 추가 호출 상한은 입력/수집 장애 복구 2회다.
  오답·무결과를 좋은 답이 나올 때까지 재시도하지 않는다.
- 각 실행은 조건을 드러내지 않는 ID로 지정한다. 작업자는 자신의 입력만 읽고 결과만 쓴다.
  6000자 이하 원문 조각으로 전부 읽으며, 계산을 위한 로컬 Python 사용은 양쪽 모두 허용한다.
  웹·다른 파일·정답·외부 API·추가 에이전트는 금지한다. 실행별 입력 해시와 task ID를 기록한다.
- JSON 결과를 파일과 최종 답변에 모두 반환하도록 해 수집 경로를 대조한다.
  파일이 없으면 해당 실행자의 최종 답변만 복원한다. 다른 실행자에게 복원을 맡기지 않는다.
  작성된 결과가 없으면 실패로 남긴다. 절차 설명은 산출물이 아니다.

## 채점과 채택

정답은 명시된 규칙을 실행하는 표준 라이브러리 참조 계산기로 작성하고 독립 사전 검토를 받는다.
모델 답변을 보기 전에 정답을 고정한다. 설명의 유창함 대신 관측 가능한 값·형식·근거 ID를 채점한다.
오브젝트의 키, 배열 순서, 문자열과 숫자 타입까지 비교한다. bool을 숫자와 같다고 보지 않는다.
JSON 객체 포장은 점수를 주지 않으며, 실제 요구 결과가 있어야 한다.
원자 값 정확도와 과제 전체 통과율을 따로 표시한다. 원자 값은 독립 표본이 아니다.

후보를 스킬에 반영하려면 다음을 모두 만족해야 한다.

1. 전체 24개 비교 칸에서 기준본보다 과제 전체 통과가 5개 이상 증가한다.
2. 두 모델 각각 통과 수가 떨어지지 않고, 확인 과제에서 2개 이상 증가한다.
3. 같은 모델·반복·과제에서 기준본이 통과한 것을 후보가 실패하는 회귀가 없다.
4. 후보의 권한/완료 상태(배포 판정) 및 원문/참조 보존 과제는 모두 통과한다.
5. 후보 추가 문자는 각 과제 기준본의 20% 이내다.

이는 제한된 과제에서 유망한 조건부 지시의 기준이다. 통계적 유의성이나 일반적 품질 향상을
입증하는 기준은 아니다. 기준 미달이면 지시를 추가하지 않는다. 동점은 기존의 보편적 우수성을
증명하지 않으며, 실패는 남기고 입력 잘림·수집 오류와 내용 오류를 구분한다.

실제 이미지 품질·공급자 API·계정 접근권한·토큰 비용은 측정하지 않는다.
`python3 benchmarks/prompt-stress/evaluate.py audit`로 기록과 점수를 오프라인 재계산한다.
