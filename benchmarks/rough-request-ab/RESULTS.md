# 대충 한 요청을 보강하는 개념의 재평가

2026-10-28. **사용자 지적이 맞다.** 앞선 raw-vs-meta 실험은 이미 상세한 명세를 주었기 때문에
‘대충 요청하면 목적·완료조건·형식을 채워 수행한다’는 스킬의 핵심 가치를 검증하지 못했다.
그 실험의 동점을 메타 프롬프트 개념 전체의 효과 없음으로 해석하면 안 된다.

## 실제로 바꾼 입력과 흐름

원요청은 ‘이거 회의 정리 좀’, ‘이 숫자들로 보고 좀 만들어줘’, ‘이분 답장 좀 써줘’,
‘프롬프트 하나 만들어줘’다. 상세 요구 형식이나 완료조건을 사용자 요청에 미리 넣지 않았다.
원래 요청과 업무 맥락은 양쪽 실행자에게 동일하게 주었다.

- raw: 짧은 요청을 직접 수행.
- meta: 실제 스킬로 목표·형식·완료조건·가정·질문을 만든 후 수행.
  자유롭게 보강하도록 했으며 이전의 SOURCE 틀 제한은 쓰지 않았다.

예를 들어 ‘이분 답장 좀’은 고객용 답장 초안, 환불 조건, 승인 미확인 상태,
확인되지 않은 처리 기간을 약속하지 않는 완료조건으로 구체화됐다.
회의 정리에는 결정·미결·담당·기한 구분이, 보고에는 비교 지표와 계산·해석 한계가 추가됐다.
목적이 없는 프롬프트 요청은 임의 주제를 만들지 않고 핵심 질문 단계로 남겼다.
이는 **명세 보강 기능이 실제로 작동한 관찰**이다.

## 출력 평가

요청 모델 Luna/Terra, effort=low, 조건별 2회, 새 에이전트 8개에서 총 32개 응답을 받았다.
두 판정자가 조건과 모델명을 가린 응답을 원래 요청·맥락 기준으로 각각 평가했다.
목적 충족·맥락·사실 경계·실용성·질문 절제의 다섯 축이며 제목/표/길이 자체에 점수를 주지 않았다.

| 판정자 요청 모델 | raw / 160 | meta / 160 | 차이 |
|---|---:|---:|---:|
| Luna | 157 | 157 | 0 |
| Terra | 158 | 160 | +2 |

실행 모델별 80점 기준 세부값은 Luna 판정자가 Luna 실행 80→77, Terra 실행 77→80;
Terra 판정자는 Luna 실행 80→80, Terra 실행 78→80이었다.
두 판정자 각각 +8점 이상과 모델별 비감소를 요구한 사전 개선 신호 기준은 미충족이다.
관측치를 사람의 선호, 통계적 유의성, 보편적 품질 향상으로 해석하지 않는다.

## 확인된 장점과 부담

- Terra raw 두 번째 답장(B07)은 승인 확인 절차는 안내했지만 전액 환불 가능 여부를 빠뜨렸다.
  두 판정자가 맥락·실용성을 각각 1점 감점했다. 대응하는 meta 답장(B08)은 이를 포함했다.
- Luna 판정자는 meta의 일부 답장 설명과 목적 확인 질문이 약간 과하다고 평가했다.
  다른 판정자는 그 감점에 동의하지 않았다.
- 32개 응답 × 5개 축 중 판정자 점수가 달랐던 것은 4칸이다.
  경제성 3칸과 승인 상태 표현의 사실 경계 1칸으로, 원문과 이유를 증거 파일에 보존했다.
- 목적 없는 요청은 양쪽 모두 질문했다. 세 완성 가능 과제는 양쪽 모두 산출물을 작성했다.
  메타만 질문을 잘했다거나 raw가 전혀 보강하지 않았다고 말할 수 없다.

메타는 빈 명세를 채웠고 일부 누락을 줄인 사례가 있었다. 다만 raw의 native agent도
스스로 상당 부분 구조화했다. 이 작은 실험에서 추가 품질 이득의 크기는 확정되지 않았다.

## 한계와 운용

업무 맥락은 두 조건에 동일하게 제공했다. 맥락 자체가 없을 때의 행동은 필수 목적 누락 사례
하나만 포함하므로, 모든 무맥락 요청에 일반화할 수 없다. 사용자가 실제로 쓴 요청을
표본으로 삼은 인간 선호 검증도 아니다. 준비 중 추가 실사용 예시는 받지 못해 합성 요청을 사용했다.

판정자는 LLM proxy이며 표현 방식으로 조건을 추측했을 가능성을 완전히 제거할 수 없다.
조건 추측·서식 보너스는 금지했고, 불일치를 공개했다. 모델/effort는 요청값이며 실제 backend는 unknown이다.
같은 에이전트의 과제와 반복 결과를 독립 표본으로 간주하지 않는다.
변환은 타깃당 한 번, 총 2회 추가됐고 그 명세를 두 반복에 재사용했다.
문자 수는 증거에 기록하지만 토큰·비용·지연으로 환산하지 않는다.

기존 스킬 기준은 유지한다. 이후 효과 검증도 **거친 요청에서의 누락 보완·의도 보존·질문 부담·결과의 활용성**을
기준으로 삼아야 하며, 상세 명세 뒤에 문장을 더하는 비교로 대체하지 않는다.
