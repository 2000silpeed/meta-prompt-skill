# Agent Team Composer 파일럿

## 질문과 범위

동일한 구조화 조합 설계 과제를 단일 에이전트, 병렬 분담 후 통합, 제작 후 독립 검토 중 어떤 구성으로 처리하는 것이 유리한가?

6개 합성 워크플로를 한 묶음으로 실행한다. 각 구성 2회, 총 6회 실행으로 케이스 판정은 36개다. 독립적인 사용자 과제 36개를 표본으로 삼은 실험은 아니다. 모델과 reasoning 설정은 현재 런타임을 상속하며 재지정하지 않는다. 다른 서비스의 실제 호출·성능 비교는 포함하지 않는다.

## 고정 조건

- 공통 입력: input/brief.md, input/cases.json.
- meta-prompt 적용: Goal/Context/Constraints/Done when, 구조화 출력·자기 검증. 카드 경로는 manifest.json에 기록.
- 비용, 속도, 서비스 능력은 합성 데이터다. 가상 latency와 가상 unit은 실제 실행 지연·비용과 구분한다.
- 최적 배정은 유한한 모든 후보 조합을 열거하는 Python evaluator로 결정한다. 입력과 채점기는 첫 실행 전 해시로 고정했다.
- 점수는 케이스당 9개 불리언 검사, 실행당 54개다. 차단 케이스에서 배정 관련 검사는 빈 배정을 검사하므로 54개의 독립 능력 지표가 아니다.
- 프롬프트 네 필드의 존재는 자동 검사하며 내용의 의미적 정확성은 별도 수동 검토 대상이다. 이 점수를 전반적인 창작 품질 점수로 부르지 않는다.
- 새 에이전트를 매 역할마다 사용하며 이전 대화를 전달하지 않는다. 입력·자신의 인계 파일만 읽도록 지시한다. 파일시스템은 공유하므로 보안 수준의 격리는 아니다.
- 외부 네트워크·유료 API·추가 하위 위임 없이 로컬 파일 및 Python 표준 라이브러리 사용 가능.
- 총 토큰 상한이 동일한 실험이 아니다. 구성별 추가 에이전트 비용은 측정하지 못하며 실제 비용은 unknown으로 기록한다.
- 각 역할은 출력과 자기 검증을 수행한다. 부모는 정답 피드백이나 답안 수정을 제공하지 않는다.

## 구성

| 구성 | 역할 | 실제 호출 수/회 |
|---|---|---:|
| single | 전체 6케이스 해결·자기 검증 | 1 |
| parallel | C01~03 담당 + C04~06 담당 동시 실행, 이후 새 통합자 | 3 |
| review | 전체 해결·자기 검증한 제작자, 이후 새 검토자가 확인·수정 | 2 |

고정 순서: 1회차 parallel → single → review, 2회차 review → single → parallel. 순서는 실행 전 정했으며 무작위 실험으로 표현하지 않는다. 구성끼리는 동시에 실행하지 않는다. 병렬 구성의 두 작업자만 동시에 실행한다.

## 측정

- 필수 조건 통과: 54개 검사 통과 수, 6개 케이스 전체 통과 수.
- 산출물 도달 시간: 시작 마커 기록 시점부터 final.json 최종 수정 시점. 호출 준비·역할 간 인계 대기 포함. 최종 채점과 보고서 작성 시간 제외.
- 첫 채점에서 시작·산출물 시각과 최종 파일 해시를 measurement.json에 고정한다. 이후 재채점은 이 기록을 사용하므로 파일 복사·Git checkout으로 변경된 mtime을 실행 시간으로 재해석하지 않는다.
- 제작 초안과 최종 결과의 점수 차이, 병렬 부분 결과와 최종 결과의 변화.
- 실제 에이전트 호출 수. 토큰·금액·서버 추론 시간은 계측 경로가 없어 unknown.
- 사용자 추가 개입 수. 이 파일럿의 초기 실행 요청과 진행 보고는 개입에 포함하지 않는다.

제한: 각 구성 2회는 통계적 우열을 주장하기에 부족하다. 현재 모델·고정 입력·도구 환경에서의 탐색 결과만 보고한다. 시간은 서버 부하와 부모 오케스트레이션 지연의 영향을 받는다. 같은 모델의 팀 구조 비교이며 meta-prompt 유무 비교나 서비스별 순위 평가가 아니다.

공통 입력·규칙과 팀 구조는 실험을 위해 사전 고정했다. 따라서 이 실험은 팀 구성 스킬의
모든 자동 선택 동작을 검증하지 않는다. 실제 도구 발견, 외부 모델 가이드 자동 로딩,
인증 실패 복구, 사용자가 자유롭게 표현한 요청의 분해 정확도는 별도 테스트가 필요하다.

## 재채점

```bash
python3 benchmarks/team-composer-pilot/evaluate.py --self-test
python3 benchmarks/team-composer-pilot/evaluate.py benchmarks/team-composer-pilot/runs/r1-single/final.json
python3 benchmarks/team-composer-pilot/report.py
```

재실행은 새 runs 디렉터리와 고정 명세로 네이티브 에이전트를 실제 호출해야 한다. 위 명령은 기존 답안을 채점할 뿐 새 모델 실행을 하지 않는다.
