# 다중 모듈 코드 회귀 수정 비교 v2

## 과제

5개 Python 모듈의 주문·재고 이벤트 엔진을 공개 계약에 맞춰 수정한다. 시간대 정규화,
할인 정수 배분, 누적 부분 취소 환불, 재고 원자성, TTL과 rollback, 중복 이벤트,
입력·출력 객체의 소유권, replay 순서가 서로 영향을 준다. 실제 결제·상점·외부 API를 사용하지 않는 합성 코드 과제다.

공개 테스트 6개를 제공한다. 별도 에이전트가 구현·공개 테스트·정답을 보지 않고
CONTRACT.md만 읽어 40개 평가 테스트를 작성했다. 기준 구현은 40/40, 결함이 삽입된
시작 코드는 20/40을 통과했다. 입력 코드·계약·평가 테스트·채점기는 첫 실험 호출 전에
manifest.json의 SHA-256으로 고정했다. 테스트 제작 호출은 비교 구성의 실행 시간·호출 수에서 제외한다.

## 구성과 실행

| 구성 | 역할 | 실험당 실제 에이전트 호출 |
|---|---|---:|
| single | 전체 코드 수정·자기 검증 | 1 |
| parallel | clock/money/inventory 담당 + engine/__init__ 담당 동시 실행, 이후 전체 통합자 | 3 |
| review | 전체 코드 수정자, 이후 독립 검토·수정자 | 2 |

각 구성 2회, 총 6회다. 순서는 실행 전에 single→parallel→review / review→parallel→single로 정했다.
구성끼리는 동시에 실행하지 않고 parallel의 두 worker만 동시에 실행한다.
각 역할은 현재 모델·reasoning 설정을 상속하고 이전 대화를 전달받지 않는 새 네이티브 에이전트다.
Meta-prompt의 목표·맥락·제약·완료 조건, 검증 및 구조화 인계 규칙으로 역할별 프롬프트를 작성했다.

각 실행은 같은 fixture의 새 복사본에서 출발한다. 에이전트는 자신의 work 디렉터리와
지정된 인계 자료만 읽는다. 다른 실행, private/, 평가기·평가 결과는 읽지 않는다.
이 격리는 지시 기반이며 파일시스템 자체는 공유한다. 평가 테스트가 악의적 접근으로부터
보호되는 보안 샌드박스라고 주장하지 않는다.

병렬 worker는 같은 work에서 서로 다른 파일만 수정한다. 기존 함수 시그니처를 계약으로
사용하며 파일 소유권을 넘는 임시 우회는 금지한다. 공개 테스트는 수정하지 않으며
자체 테스트는 지정 파일에 추가할 수 있다. 마지막 통합자는 shop 전체를 수정할 수 있다.

외부 네트워크·라이브 서비스·패키지 설치·추가 에이전트 생성은 사용하지 않는다.
역할별 토큰·시간 상한이 동일한 실험은 아니다. 각 역할은 자기 테스트 실패를 수정할 수
있지만 평가용 테스트의 피드백을 받지 않는다. 부모는 답안에 패치를 제공하지 않는다.

## 평가

- 고정된 40개 평가 테스트 통과 수. subTest 실패가 있으면 해당 test 메서드는 통과하지 않은 것으로 계산.
- 공개 테스트 통과·원본 보존 확인.
- review의 제작 초안과 최종본, parallel의 worker 완료 상태와 통합 최종본을 각각 채점.
- 시작 마커부터 최종 completion.json까지의 벽시계 시간. 호출 준비·인계 대기·중간 채점 포함.
- 시간과 소스 해시를 measurement.json에 고정하여 checkout/파일 복사 후의 mtime 변화와 구분.
- 실제 역할 호출 수와 작성·수정된 코드. 금액·토큰 사용량은 미측정으로 유지.

기준 구현의 만점은 평가기가 계약의 모든 가능한 입력을 검증한다는 증거가 아니다.
새 에이전트의 결과를 본 뒤 유리하거나 불리하게 테스트를 바꾸지 않는다.
각 구성 두 번의 같은 문제 반복이므로 서비스 순위, 통계적 유의성, 모든 코딩 작업의 우열을 주장하지 않는다.
구성은 비교를 위해 사전에 고정했다. 자동 서비스 발견·팀 선택의 정확도는 이 실험의 평가 대상이 아니다.

## 재채점

```bash
python3 benchmarks/team-composer-regression/grade.py \
  --candidate benchmarks/team-composer-regression/runs/r1-single/work \
  --output benchmarks/team-composer-regression/runs/r1-single/regraded.json
python3 benchmarks/team-composer-regression/report.py
```

이 명령은 기존 코드의 재채점과 보고서 재생성만 수행한다. 새 모델 실험을 하려면
새 runs 디렉터리에서 같은 고정 명세로 네이티브 에이전트를 실제 호출해야 한다.

## 사후 탐색 검사

r1-review에서 발견된 큰 정수 직렬화 한계를 바탕으로 별도 검사를 작성했다.
나머지 참여 에이전트에게 이 발견·검사를 전달하지 않았으며, 모든 실행이 끝난 뒤
각 최종본과 보관된 중간 단계에 동일하게 실행했다. `python3 benchmarks/team-composer-regression/posthoc.py`로
재현한다. 검사 출처·선택 편향·해시는 private/probe-provenance.json에 기록했다.
이 결과는 고정된 40개 테스트 점수에 포함하지 않으며, 팀의 일반적 품질 순위를 입증하지 않는다.
