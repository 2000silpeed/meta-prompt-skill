# Agent Team Composer 기획 · v0.1

## 목적

“모델에 어떻게 지시할까?”를 해결하는 meta-prompt 위에 “어떤 역할을 어떤 서비스에 맡기고 어떻게 합칠까?”를 결정하는 스킬을 추가한다. 사용자의 작업과 현재 환경에 맞는 최소 팀을 구성하고, 역할별 프롬프트는 기존 가이드북을 단일 원본으로 사용한다.

서비스는 AI 실행 환경과 제작 플랫폼을 포함한다. 업무 커넥터는 작업 도구로 연결할 수 있지만 독립적인 추론 에이전트로 취급하지 않는다.

## 구조

```text
사용자 목표·완료 기준·제약
          ↓
Agent Team Composer
  환경 관측 → 작업 의존성 → 역할·서비스 배정
          ↓
meta-prompt
  registry → 모델 index → 필요한 카드 → 역할별 작업 지시
          ↓
현재 에이전트 / 네이티브 서브에이전트 / 연결된 외부 서비스
          ↓
결과 회수 → 인계 확인 → 통합 검증 → 결과물
```

## 설계 결정

| 결정 | 이유 |
|---|---|
| 별도 스킬 + 기존 스킬에서 연결 | 단일 프롬프트 사용 흐름을 유지하면서 팀 구성 요청을 처리 |
| 역할·서비스·모델을 별도 필드로 기록 | 같은 모델의 여러 역할과 실제 여러 서비스의 협업을 구분 |
| 가이드북 재사용 | 복사본의 버전 불일치와 프롬프트 규칙 중복 방지 |
| 환경 관측 후 배정 | 설치 목록만 보고 가짜 실행 경로를 만들지 않음 |
| 최소 팀, 동시 실행 한도 준수 | 불필요한 팀장·검수자와 조율 비용 방지 |
| plan / execute 구분 | 구성 요청의 범위를 지키고 실행 요청은 계획에서 멈추지 않음 |
| YAML 명세와 프롬프트 | 작업 소유권·선후 관계·실행 결과를 확인 가능한 형태로 남김 |
| 서비스 순위표 대신 선택 근거 | 작업·가격·연결 환경에 따라 달라지는 조건을 반영 |

## v0.1 제공 범위

- 작업 분해, 서비스 후보의 가용성 확인, 역할 배정, 메타 프롬프트 컴파일 지침.
- 네이티브 서브에이전트와 현재 에이전트 순차 실행, 확인된 외부 도구에 대한 실행 계약.
- 의존성·결과 상태·재시도·통합 검증 명세와 재사용 템플릿.
- 단일 작업, 미연결 서비스, 예산 제한, 실패 전파 등의 평가 시나리오.

이 버전은 에이전트가 읽고 실행하는 스킬 패키지다. 독립 스케줄러, 서비스 API 어댑터,
자동 결제 제어기, 벤치마크 기반 최적화 엔진은 포함하지 않는다.
서로 다른 모델의 실제 호출은 해당 서비스 연결과 호스트의 모델 선택 기능이 있어야 한다.

## 다음 개선의 기준

먼저 실제 사용 사례에서 팀 구성 시간, 인계 오류, 완료 기준 충족률, 관측 가능한 비용을 기록한다.
같은 요청을 단일 에이전트와 팀에 맡길 수 있는 허가된 비교에서 팀 구성이 유리한지 평가한다.
반복되는 서비스 발견·상태 조회가 확인되면 그 부분부터 실행 가능한 어댑터로 추출한다.
충분한 관측 없이 서비스별 점수표나 자기 학습 기능을 추가하지 않는다.

평가 범위와 결과는 [agent-team-validation.md](agent-team-validation.md)에 기록한다.
