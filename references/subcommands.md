# meta-prompt 서브커맨드 절차

SKILL.md에서 `/meta-prompt refresh|eval|add`가 호출됐을 때만 이 파일을 읽는다. `$GB`는 스킬 베이스 디렉토리의 `guidebooks/`다.

## `/meta-prompt refresh <model>`

1. `$GB/<model-id>/sources.yaml`의 URL을 현재 환경의 웹 도구로 열어 확인한다. `local:`은 실제 파일·리소스가 있을 때만 읽고, 누락·접근 실패·과거 세션 식별자는 확인 불가로 기록한다.
2. 실제 읽은 근거와 카드의 주장을 대조해 **변경된 카드만** 수정한다. 새 주제가 생겼으면 카드 추가를 제안하고, 모델/API 문서와 플랫폼·내장 도구의 지원 범위를 구분한다.
3. 확인한 소스의 `fetched`와 검토한 카드의 날짜·검증 범위를 기록한다. 전체 카드의 주장을 현재 근거로 확인했을 때만 registry의 날짜와 `verification: verified`를 갱신한다. 일부만 확인했으면 `partial`과 확인·미확인 범위를 남기고, 모델 전체 및 미검토 카드의 기존 날짜를 유지한다. 근거 없는 제작 권장은 `knowledge-based`로 남긴다.
4. 변경 내용과 확인 불가·미검토 범위를 보고한다. 수집에 실패했거나 일부만 검토한 결과를 "전체 변경 없음"이나 "전체 검증 완료"로 표현하지 않는다.

## `/meta-prompt eval [<model>] <요청>`

변환이 해당 과제에서 유용했는지 A/B로 비교한다.

1. 요청을 변환 플로우로 처리해 **원본 프롬프트**와 **변환본 프롬프트**를 준비.
2. 타깃 모델의 실행 경로가 세션에 있어야 한다 — 없으면 실행 불가를 알리고 두 프롬프트만 전달한다. 승인된 평가 예산을 재사용하며, 새 비용이 필요하면 양쪽 실행의 예상 호출 수·비용을 확인받는다.
3. 실행 전에 입력·모델 버전·설정·평가 기준을 고정하고 두 프롬프트를 동일 조건으로 실행한다. 과업 충족·형식 준수·완성도와 추가 턴 수를 나눠 비교한다. 필수 입력·참조·권한·비용을 확인하는 질문은 정당한 보류로 평가하고, 이미 주어진 정보를 다시 묻거나 안전하게 추론 가능한 내용을 묻는 경우와 구분한다. 한 쌍의 결과를 보편적 성능 향상으로 일반화하지 않는다.
   수치·분류·원문 보존은 고정 정답과 독립 검사로 채점 결과를 대조한다. 입력 잘림·빈 응답·수집 오류는 내용 오답과 구분하고, 복구 시 원래 기록·변경 이유·실제 입력의 연결을 보존한다.
4. 변환본이 우세하지 않으면 그 사실을 정직하게 보고하고, 원인이 된 카드의 개선점을 기록한다 (가이드북 피드백 루프).

## `/meta-prompt add <model>`

1. 제공된 공식 URL을 우선 확인하고, 없으면 현재 웹 도구로 공식 문서를 찾는다. 제공자나 버전이 실제로 모호할 때만 질문한다.
2. `$GB/<model-id>/` 생성: `sources.yaml` → 수집 → 카드 증류(주제당 1카드, 간결하게) → `index.yaml`(카드 `when` + 슬롯 정의).
3. registry에 모델 등록 (aliases 포함).
4. 카드 초안을 사용자 검토받고 확정.
