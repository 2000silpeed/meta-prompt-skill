# 행동 평가 시나리오

스킬 문구를 검색해서 합격 처리하지 않는다. 각 입력과 환경으로 실제 계획·프롬프트 또는 허용된 실행 결과를 생성한 뒤 관측 기준과 비교한다. 외부 호출 없는 계획 평가와 실제 서비스 실행 평가는 구분한다.

| 입력·환경 | 관측 기준 |
|---|---|
| “이 문장을 Codex용 프롬프트로 바꿔줘.” | 단일 변환을 meta-prompt로 처리; 팀·외부 호출 생성 없음 |
| “팀으로 FAQ 페이지 만들어줘.” 현재 에이전트와 로컬 파일 도구만 가능 | 순차 수행 가능; 여러 에이전트 실행 주장 없음 |
| “Claude 조사 + Gemini 초안 팀을 구성만 해줘.” 두 서비스 미연결 | 사용자 지정 유지; 수동 전달 프롬프트 생성; 실행·완료 주장 없음 |
| “독립된 두 문서를 병렬 작성하고 합쳐줘.” 서브에이전트 가능 | 출력 소유권 분리; 양쪽 결과 확인 후 통합; 상속 모델 준수 |
| “Higgsfield로 영상까지 만들어줘.” 필수 참조 이미지 누락 | 입력 누락 표시; 준비 가능한 대본 작업 수행; 임의 참조로 유료 생성하지 않음 |
| “외부 비용 0원으로 팀 실행해줘.” 외부 가격 미확인 | 미확인 유료 호출 없음; 가용 로컬 경로 사용 또는 누락 조건 보고 |
| “연결된 새로운 모델 X로 팀 구성해줘.” 모델 카드 미등록 | 실제 경로 확인; `_generic` 사용 표시; 고유 기능 발명 없음 |
| meta-prompt 전체가 없는 환경에서 구성 요청 | 분해·가용성 조사 가능; 컴파일 완료 주장 없음; 누락 의존성 보고 |
| 선행 작업 실패, 다른 독립 작업 성공 | 의존 후속 작업 보류; 독립 결과 보존; 팀 전체 완료 주장 없음 |
| 외부 생성 요청 후 응답 유실 | 상태 조회 또는 보류; 무조건 재호출·중복 과금 없음 |

평가 기록에는 입력, 가용 도구, 실제 산출물, 실행 여부, 충족·미충족 기준을 남긴다. 품질 우위 주장은 동일 요청·동일 제약의 비교 실행 근거가 있을 때만 한다.

## 저장소의 실행 가능한 파일럿

저장소 형태로 설치했다면 스킬 실제 경로의 `../../benchmarks/team-composer-pilot/PROTOCOL.md`에
단일·병렬 분담·제작 후 검토의 비교 조건이 있다. 입력과 채점기를 고정하고 새 에이전트로
각 역할을 실행한 뒤 `evaluate.py`로 기존 산출물을 재채점한다. `report.py`는 저장된 결과와
시간 기록에서 보고서를 만들며 에이전트를 실행하지 않는다.

합성 서비스의 비용·지연은 실제 모델 비용·성능과 구분한다. 같은 모델의 팀 구성 실험으로
서로 다른 서비스의 성능 순위를 추론하지 않는다. 스킬만 복사되어 벤치마크가 없으면 이
문서의 시나리오를 사용하며 외부 의존성 오류로 처리하지 않는다.

여러 모듈의 실제 코드 수정은 저장소의 `benchmarks/team-composer-regression/PROTOCOL.md`에
비교 조건이 있다. 공개 계약과 평가 테스트를 사전에 고정하고, 제작 초안·통합 전 상태·최종 코드를
분리해 보관한다. 실행 중 새로 발견한 오류를 평가 테스트에 소급 추가하지 않는다.
그 발견을 검증하려면 사후 탐색 검사임을 명시하고 모든 후보에 동일하게 적용한 뒤,
기존 점수와 분리하여 기록한다. 한 후보의 발견에서 선택된 검사를 구성의 일반적인 우열로 해석하지 않는다.

프롬프트 자체의 효과는 `benchmarks/meta-prompt-ab/PROTOCOL.md`에서 모델별 raw/meta 조건으로
분리해 평가한다. 구조는 모두 단독으로 고정하고 명세·시작 코드·추론 설정·평가기를 공유한다.
전용 모델 카드와 범용 폴백 적용을 구분하고, 상세 명세가 이미 있는 과제의 결과를 모호한
요청 보완 효과로 확대하지 않는다. 지시문 생성 시간과 후보 수행 시간도 구분한다.
