# 실행·인계 계약

## 실행 경로

호스트가 제공하는 네이티브 서브에이전트 도구를 우선한다. 이 스킬은 실행 요청에 대해 독립 작업의 서브에이전트 위임을 허용하지만 상위 지침과 도구 제약을 따른다. 내부 역할을 위해 사용자 소유의 새 태스크·채팅을 생성하지 않는다.

서브에이전트 도구가 없으면 현재 에이전트가 작업을 순차 수행하고 `sequential`로 기록한다. 역할별 채팅을 흉내 내면서 여러 모델이 실행됐다고 보고하지 않는다. 외부 서비스 호출은 확인된 커넥터·CLI·API만 사용한다. 명세에 적힌 가상의 도구 이름을 호출하지 않는다.

기존 사용자 허가와 비용 범위를 재사용한다. 추가 유료 호출, 외부 전송·게시 등 별도 허가가 필요한 단계는 구체적인 입력·대상·알려진 비용을 준비한 뒤 해당 단계에서만 확인한다. 허가 범위 안의 로컬 작업은 진행한다. 사용자 지정 서비스가 필수인데 연결되지 않으면 해당 작업을 보류하며, 수동 전달용 프롬프트와 정확한 누락 조건을 제공한다.

## 작업 상태

`planned → ready → running → completed`를 기본으로 한다.

- `ready`: 선행 작업의 검증된 결과와 필요한 허가·입력·실행 경로가 준비됨.
- `running`: 실제 도구 호출 또는 현재 에이전트의 작업 수행을 시작함.
- `completed`: 출력이 존재하고 해당 작업의 완료 기준을 확인함.
- `failed`: 실행했으나 완료 기준 미충족.
- `blocked`: 입력·권한·필수 연결 등의 조건 누락. 원인과 재개 조건을 남김.
- `manual-handoff`: 자동 실행 경로 없이 프롬프트·입력을 전달한 상태. 완료가 아님.

하위 작업이 실패·보류되면 그 결과를 요구하는 후속 작업도 보류한다. 독립 작업은 계속한다. 팀 전체 완료는 필수 작업과 통합 완료 기준이 모두 충족될 때만 보고한다.

## 배정과 결과 회수

작업마다 담당자 하나와 출력 소유권을 정한다. 선행 작업 ID의 중복·누락·순환이 없는지 확인한다. 선행 결과가 필요한 프롬프트는 계약부터 준비할 수 있지만, 실제 결과의 경로·내용을 반영한 최종본으로 실행한다.

위임 시 관련 목표·필수 제약·입력·쓰기 범위·완료 기준을 전달한다. 재위임은 명세의 팀 규모를 임의 확장하지 않는 범위에서만 허용한다.

결과 회수 형식:

```text
task_id:
status: completed | failed | blocked
outputs: 실제 경로 또는 제공한 본문
verification: 수행한 검사와 결과; 미실행 항목은 구분
issues: 남은 문제와 후속 작업에 미치는 영향
usage: 관측된 비용·시간 또는 unknown
```

도구가 반환한 작업 ID를 저장하고 지원되는 대기 기능으로 완료를 회수한다. 중복 실행하지 않는다. 외부 작업 응답이 불명확하면 제공되는 상태 조회나 멱등성 키로 확인하고, 확인 수단이 없으면 재호출 대신 상태를 보고한다.

실패 시 원인이 명확하고 안전하게 수정할 수 있는 경우에 한해 기본 1회 수정·재시도를 허용한다. 사용자 지정 한도가 있으면 따른다. 동일 원인이 반복되면 `failed`와 원인을 기록한다. 인증·예산·필수 입력 누락은 반복 호출로 해결하지 않는다.

## 통합 검증

오케스트레이터가 파일·출력 형식·인계 계약과 원래 완료 기준을 직접 확인한다. 담당자의 완료 보고만으로 완료 처리하지 않는다. 결과에 영향을 주는 충돌은 소유자에게 수정시키거나 오케스트레이터가 통합한다. 재검증은 변경된 결과와 영향 범위에 맞춘다.
